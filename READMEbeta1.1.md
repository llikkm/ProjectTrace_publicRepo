# SRDP 大屏幕显示交互系统项目说明与交接

版本 beta1.1  
更新日期 2026-11-11  
依据《申报书beta1.3.3.1.docx》及本轮已确认的交互方案整理。

## 先读这一页

项目正式名称为“基于激光雷达的大屏幕显示交互系统开发”。使用者用交互笔在固定投影平面上点击、拖动和批注。单台二维雷达提供笔身前端的位置，笔尖开关提供接触状态，电脑估计笔尖坐标并绘制笔迹。

雷达由指导教师提供，型号已确定为 PAVO 系列 SIMO-LS-20H。笔端采用 ESP32-S3，现有项目目录包含 LSM6DS3TR-C 的读取示例。投影仪计划借用。申报经费按最新申报书为 4500 元。

近程系统是结题主线。IMU 已列入近程倾斜补偿研究，真实 IMU 远程空鼠安排在后期，根据近程完成情况开展拓展。近远程共用接口先用鼠标模拟远程输入验证。

交互笔采用短外露笔尖，雷达直接检测与笔壳一体的笔身前端检测段。握持区和按键后移，通过外形引导手指位置。首版检测段采用与笔轴同轴的规则圆柱截面，具体尺寸由回波和握持实验确定。

软件采用可移动、可收起的桌面工具条，在透明覆盖层上为桌面或当前软件添加批注，也能打开独立白板。图 4 已体现这一概念。操作工具将点击交给下层软件，画笔工具将轨迹交给批注层。近远程模式与操作、画笔工具分别管理。

截至本轮对话，尚未提供雷达接入和定位实测记录。后续交接优先读取本文件，并检查用户指定的最新申报书和内部实现步骤。

## 一 当前范围和任务优先级

- 单人单笔、单台固定雷达，面向竖直的固定平整投影面。
- 近程实现桌面点击、按住拖动、接触书写及抬笔断笔，软件提供清屏和保存。
- 开发先在小画布验证输入，再扩展到桌面透明批注层和独立白板。
- 近程倾斜补偿先做固定笔尖的短时实验，再比较慢速书写效果。
- 共用接口采用模拟输入验证，真实 IMU 空鼠作为后期拓展单独记录进展。

近程演示流程为点击桌面快捷方式、打开软件、完成规定书写和拖动。后期接入真实 IMU 时，再补充空鼠打开应用及返回近程继续操作。

## 四 数据处理与软件组织

系统连接保持两条采集路径。

```text
SIMO-LS-20H ──以太网 / 厂家 SDK──→ 电脑
笔尖开关 / 按键 / IMU ──ESP32-S3 / USB 串口──→ 电脑
电脑 ──桌面批注层 / 白板 / 鼠标事件──→ 投影显示
```

定位流程按申报书的八个环节组织。

```text
扫描数据接入 → 有效区域筛选 → 笔端检测 → 目标跟踪
→ 笔尖位置估计 → 投影坐标映射 → 接触事件融合 → 界面响应
```

雷达扫描点先由距离和角度换算为毫米坐标，筛除零距离等无效点。按相邻点距离分组，结合检测段尺寸筛选目标，再用上一帧位置和宽度变化关联。缺少有效位置时暂停绘制，目标超时后重新搜索，重新捕获后另起一段。

雷达看到检测段朝向自身的表面，需要用已知截面和结构标定估计笔轴交点。倾斜补偿之后再映射到屏幕像素，标定所用坐标与运行时的坐标处理链保持一致。

软件开发先保留鼠标画布，完成统一输入入口与回放。再实现独立的浮动工具条和透明置顶批注层。工具条区域优先处理按钮操作，操作模式生成桌面鼠标事件，画笔模式更新批注笔迹。独立白板使用同一套绘图逻辑，分别保存白板和桌面的笔迹。

可参考 gInk 的简洁工具条、ppInk 的桌面批注与鼠标穿透、OpenBoard 的桌面和白板切换。具体实现沿用项目的 Python/PySide6 路线，软件功能按阶段推进。

- [gInk](https://github.com/geovens/gInk)
- [ppInk](https://github.com/pubpub-zz/ppInk)
- [OpenBoard](https://github.com/OpenBoard-org/OpenBoard)

## 六 姿态补偿与时间处理

板面向右为 x，向上为 y，向使用者为 z。u 表示从笔尖指向笔尾的笔轴单位向量，并已变换到板面坐标系。x_detect、y_detect 表示经过结构标定得到的笔轴与扫描区域交点。

当扫描面与板面平行且间距为 h 时，使用以下理想轴线关系。

```text
d = h × tan(θ)
x_tip = x_detect − h × u_x / u_z
y_tip = y_detect − h × u_y / u_z
```

d 是沿板面的偏移，θ 从板面法线量起。h=10 mm、θ=45° 时 d 约为 10 mm。h 的实际取值由安装及回波实验确定。仅在 u_z 大于预设正阈值的握姿范围内应用补偿。

先用夹具固定笔尖，测试 0°、15°、30°、45°，比较补偿前后的点位。六轴 IMU 的航向缺少绝对参考，需要建立相对板面的初始姿态，并记录复位后的经过时间和漂移。静态实验完成后再接慢速书写。

保留雷达设备时间、笔端设备时间和电脑接收时间。程序先用电脑统一时钟分析处理耗时，再研究设备时间对齐。动态补偿需要匹配同一时刻附近的位置和姿态，端到端延迟用慢动作录像测量。

## 七 考核指标

以下均为《申报书beta1.3.3.1》的计划目标。

| 项目 | 口径 |
| --- | --- |
| 工作范围 | 约 1.0 m × 0.6 m，单人单笔，雷达到最远测试点约 2 m 内 |
| 定位 | 九个独立检查点各重复采样 10 次，平均平面误差 ≤20 mm |
| 点击 | 直径约 50 mm 目标，50 次，至少 45 次成功 |
| 拖放 | 20 次规定起终点拖放，至少 18 次成功 |
| 接触 | 40 次，至少 36 次识别正确 |
| 悬停误落笔 | 40 次，笔尖离面 5–20 mm，每次 2 s，最多 2 次误落笔 |
| 连续书写 | 50–150 mm/s，直线、圆、折线及约 120 mm 高文字，无遮挡时有效跟踪帧占比 ≥90% |
| 延迟 | 不低于 120 fps 录像，中位数 ≤100 ms |

定位参考点与检核点分开，记录每次采样时的握姿和平均帧数。悬停按每次 2 秒试验统计。有效帧应满足目标识别和位置有效条件，原始帧数按雷达扫描记录统计。最长连续丢失时间可作为内部分析项另行记录。

创新点中的接触触发对照需要两种策略各做 40 次悬停试验，并做接触识别对照。可以共用原始记录和同一套动作，分别计算两种策略的结果。

## 八 远程拓展与键位

近程 IMU 用于姿态补偿研究，远程 IMU 用于后期空鼠拓展。模拟切换先检查结束笔画、释放按下状态及输入源交接，再返回近程继续操作。

| 控制件 | 已确认的远程拓展行为 |
| --- | --- |
| 模式开关 | 切换近远程，切换前结束当前操作并释放按下状态 |
| 点击键 | 按下产生鼠标按下，松开产生释放，支持点击与拖动 |
| 复位键 | 按住释放按下状态、暂停姿态驱动、光标归中，松开更新姿态零位 |
| 固定键 | 按一次锁定当前位置，期间点击键可用，再按一次更新零位并恢复移动 |

远程采用相对零位的水平、竖直偏转角控制光标速度，并设置零位死区。图 1 的 A/B/C/L/R 为外观示意，具体物理键与功能的对应关系留待结构装配确定。

## 十二 协作方式与文字习惯

- 使用中文，讲解尽量白话，步骤具体到能动手执行。涉及公式时先说明符号和物理位置。

- 信息来源优先论文和官方资料。中文或中国网站资料限于强相关内容，例如这台雷达的厂家文档。
- 审查任务报告问题，修改按用户授权执行。用户新补充的偏好和方案应更新到后续交接材料中。
- 小段文字直接在聊天给出。文件按用户指定的命名方式另存版本，使用用户最新手动修改的版本为基准。
- 申报书修订采用蓝字正文和蓝字批注。新增或改写正文使用 `#0000FF`，批注写明版本、修改理由及待审阅的设计选择。删除内容通过相关位置批注说明，过时批注同步更新。
- 内部实现步骤采用干净版本，使用正常正文颜色，清理旧修改标记和重复文字，便于团队直接阅读使用。
- 示意图独立提供可编辑 SVG 和 PNG。图片插入文档按用户当次要求执行，保留用户自行修改图稿的工作方式。
- 硬件接线和上传由用户动手，分小步核对实物后推进，实验数量保持可执行。
- 后续任务默认按四人分配，采用成员 A/B/C/D 标记，写清每人的职责、阶段交付物和配合关系，结合实际进度平衡工作量。
